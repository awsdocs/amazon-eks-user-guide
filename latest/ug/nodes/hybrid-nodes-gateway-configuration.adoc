[#hybrid-nodes-gateway-configuration]
= EKS hybrid nodes gateway configuration reference
:info_titleabbrev: Configuration reference

[abstract]
--
Complete reference for all Helm chart values, CLI flags, and environment variables for the Amazon EKS hybrid nodes gateway.
--

This page documents all configurable parameters for the Amazon EKS hybrid nodes gateway. For installation instructions, see <<hybrid-nodes-gateway-getting-started>>. For an overview of the gateway, see <<hybrid-nodes-gateway-overview>>.

[#hybrid-nodes-gateway-helm-values]
== Helm chart values

The following table lists all values in the `eks-hybrid-nodes-gateway` Helm chart. You can set these values using `--set` flags or a custom `values.yaml` file during `helm install` or `helm upgrade`.

[%header,cols="1,1,1,1,3"]
|===
|Value |Type |Default |Required |Description

|`image.repository`
|string
|`""`
|Yes
|Container image repository for the gateway image.

|`image.tag`
|string
|Chart `appVersion`
|No
|Image tag. Defaults to the `appVersion` defined in `Chart.yaml`.

|`image.pullPolicy`
|string
|`IfNotPresent`
|No
|Image pull policy. Valid values: `Always`, `IfNotPresent`, `Never`.

|`replicas`
|integer
|`2`
|No
|Number of gateway pod replicas. Use `2` for high availability.

|`namespace`
|string
|Release namespace
|No
|Namespace for gateway resources. Defaults to the Helm release namespace if not set.

|`createNamespace`
|boolean
|`true`
|No
|Create the namespace resource if it doesn't already exist.

|`nodeLabel`
|string
|`hybrid-gateway-node`
|No
|Node label key used to select gateway nodes. Nodes must have this label set to `"true"`.

|`vpcCIDR`
|string
|`""`
|Yes
|VPC CIDR block used for Cilium VTEP configuration. Example: `10.0.0.0/16`.

|`podCIDRs`
|string
|`""`
|Yes
|Comma-separated list of pod CIDRs used by Cilium on hybrid nodes. Example: `10.85.0.0/16,10.86.0.0/16`.

|`routeTableIDs`
|string
|`""`
|No
|Comma-separated list of VPC route table IDs to program with hybrid pod routes. Example: `rtb-0123456789abcdef0,rtb-0123456789abcdef1`.

|`autoMode.enabled`
|boolean
|`true`
|No
|Enable EKS Auto Mode integration. When `true`, the chart adds an `eks.amazonaws.com/compute-type: auto` node selector and uses a zero-downtime rolling update strategy. Set to `false` for managed node groups or self-managed nodes.
|===

[#hybrid-nodes-gateway-install-examples]
=== Example install commands

*EKS Auto Mode* (default):

[source,bash,subs="verbatim,attributes"]
----
helm install hybrid-gateway oci://<your-ecr-registry>/eks-hybrid-nodes-gateway \
  --namespace hybrid-gateway \
  --set image.repository=<your-ecr-registry>/eks-hybrid-nodes-gateway \
  --set vpcCIDR=<your-vpc-cidr> \
  --set podCIDRs=<your-hybrid-pod-cidrs> \
  --set routeTableIDs=<your-route-table-ids>
----

*Managed node groups or self-managed nodes*:

[source,bash,subs="verbatim,attributes"]
----
helm install hybrid-gateway oci://<your-ecr-registry>/eks-hybrid-nodes-gateway \
  --namespace hybrid-gateway \
  --set image.repository=<your-ecr-registry>/eks-hybrid-nodes-gateway \
  --set autoMode.enabled=false \
  --set vpcCIDR=<your-vpc-cidr> \
  --set podCIDRs=<your-hybrid-pod-cidrs> \
  --set routeTableIDs=<your-route-table-ids>
----

|`NODE_IP`

|`--vpc-cidr`
|`VPC_CIDR`
|string
|—
|VPC CIDR block used for Cilium VTEP configuration. Set from the `vpcCIDR` Helm value. Required.

|`--pod-cidrs`
|`POD_CIDRS`
|string
|—
|Comma-separated list of hybrid pod CIDRs. Set from the `podCIDRs` Helm value. Required.

|`--route-table-ids`
|`ROUTE_TABLE_IDS`
|string
|—
|Comma-separated list of VPC route table IDs to update with hybrid pod routes. Set from the `routeTableIDs` Helm value. Optional.

|`--aws-region`
|`AWS_REGION`
|string
|Auto-detected
|{aws} Region for route table API calls. Auto-detected from EC2 instance metadata if not set.

|`--aws-instance-id`
|`AWS_INSTANCE_ID`
|string
|Auto-detected
|EC2 instance ID of the gateway node. Auto-detected from EC2 instance metadata if not set.

|`--leader-election-id`
|`LEADER_ELECTION_ID`
|string
|`hybrid-gateway-leader`
|Name of the Kubernetes Lease object used for leader election.

|`--leader-election-lease-duration`
|—
|duration
|`3s`
|Duration that non-leader candidates wait after observing a leadership renewal before attempting to acquire the lease.

|`--leader-election-renew-deadline`
|—
|duration
|`2s`
|Interval between leadership renewal attempts by the active leader. Must be less than `--leader-election-lease-duration`.

|`--leader-election-retry-period`
|—
|duration
|`1s`
|Duration between retry attempts for both the leader and non-leader candidates.

|`--metrics-bind-address`
|—
|string
|`:10080`
|Address and port for the Prometheus metrics endpoint.

|`--health-probe-bind-address`
|—
|string
|`:8088`

|`--debug`
|`DEBUG`
|boolean
|`false`
|Enable debug-level logging. Set the `DEBUG` environment variable to `"true"` to enable.

[#hybrid-nodes-gateway-auto-vs-mng]
== Auto Mode vs. managed node group configuration

The `autoMode.enabled` Helm value controls two behaviors in the Deployment template:

[%header,cols="1,2,2"]
|===
|Behavior |`autoMode.enabled=true` (default) |`autoMode.enabled=false`

|*Node selector*
|Adds `eks.amazonaws.com/compute-type: auto` in addition to the gateway node label.
|Uses only the gateway node label (`hybrid-gateway-node: "true"`).

|*Rolling update strategy*
|`maxSurge: 1`, `maxUnavailable: 0` — ensures zero downtime during upgrades by starting a new pod before terminating the old one.
|`maxSurge: 0`, `maxUnavailable: 1` — terminates the old pod before starting a new one, because node capacity is pre-provisioned.
|===

When using EKS Auto Mode, the Helm chart creates a `NodePool` resource that automatically provisions EC2 instances for the gateway. When using managed node groups or self-managed nodes, you must provision and label the nodes yourself before installing the chart.

For all deployment targets, the Deployment uses `hostNetwork: true` and requires the `NET_ADMIN` capability. Pod anti-affinity ensures that the two gateway pods run on separate nodes.

[#hybrid-nodes-gateway-leader-tuning]
== Leader election tuning

The gateway uses Kubernetes Lease-based leader election to maintain an active-standby model. The default parameters are tuned for fast failover:

[%header,cols="1,1,3"]
|===
|Parameter |Default |Description

|`--leader-election-lease-duration`
|`3s`
|How long a non-leader waits after the last observed lease renewal before trying to acquire the lease. Lower values detect leader failure faster but increase the risk of false failovers during transient network issues.

|`--leader-election-renew-deadline`
|`2s`
|How frequently the active leader renews the lease. Must be less than the lease duration.

|`--leader-election-retry-period`
|`1s`
|How frequently candidates retry acquiring or renewing the lease.
|===

With the default values, the expected failover time when the active gateway fails is approximately 15–30 seconds. This includes the time for the standby to detect the lease expiration, acquire the lease, and run the leader setup sequence (VPC route table updates and Cilium VTEP configuration).

[#hybrid-nodes-gateway-leader-tuning-guidance]
=== When to adjust leader election parameters

* *Increase lease duration* if you observe frequent leader transitions caused by transient network latency between gateway pods and the Kubernetes API server.
* *Decrease lease duration* if you need faster failover detection and your network between gateway nodes and the API server is reliable and low-latency.
* *Increase retry period* to reduce API server load from leader election in large clusters.

[NOTE]
====
The `--leader-election-renew-deadline` must always be less than `--leader-election-lease-duration`. If the renew deadline exceeds the lease duration, the leader may lose the lease before it can renew.
====
