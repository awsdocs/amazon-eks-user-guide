= Capture network traffic on a managed node using kubectl and S3
:info_titleabbrev: Capture network traffic

[abstract]
--
Learn how to capture network traffic on an Amazon EKS managed node using the node monitoring agent and tcpdump.
--

Learn how to capture network traffic on an Amazon EKS managed node that has the node monitoring agent. The agent runs tcpdump on the node, compresses capture files, and uploads them to your S3 bucket.

== Prerequisites

Make sure you have the following:

* An existing Amazon EKS Auto Mode cluster with the node monitoring agent. For more information, see <<node-health>>.
* The `kubectl` command-line tool installed and configured to communicate with your cluster.
* The {aws} CLI installed and logged in with sufficient permissions to create S3 buckets and objects.
* A recent version of Python 3 installed.
* The {aws} SDK for Python 3, Boto 3, installed.
* The PyYAML library installed (`pip install pyyaml`).

== Step 1: Create S3 bucket destination (optional)

If you don't already have an S3 bucket to store the capture files, create one. Replace [.replaceable]`bucket-name` and [.replaceable]`region` with your values.

[source,bash,subs="verbatim,attributes,quotes"]
----
aws s3api create-bucket --bucket [.replaceable]`<bucket-name>` \
    --region [.replaceable]`<region>` \
    --create-bucket-configuration LocationConstraint=[.replaceable]`<region>`
----

NOTE: The `--create-bucket-configuration` parameter is required for all regions except `us-east-1`.

== Step 2: Start packet capture

Use the `start-capture.py` script from the https://github.com/aws/eks-node-monitoring-agent[node monitoring agent repository] (`tools/start-capture.py`) to generate pre-signed S3 credentials, create the `NodeDiagnostic` resource, and apply it to your cluster.

. Identify the node you want to capture traffic from.
+
[source,bash,subs="verbatim,attributes,quotes"]
----
kubectl get nodes
----

. Save the https://github.com/aws/eks-node-monitoring-agent/blob/main/tools/start-capture.py[start-capture.py] script from the node monitoring agent repository to your local machine, then run it. Replace [.replaceable]`<bucket-name>` and [.replaceable]`<node-name>` with your values.
+
[source,bash,subs="verbatim,attributes,quotes"]
----
python3 start-capture.py --bucket [.replaceable]`<bucket-name>` --node [.replaceable]`<node-name>`
----
+
Common options:
+
[source,bash,subs="verbatim,attributes,quotes"]
----
# Capture for 5 minutes on eth0 with a filter
python3 start-capture.py --bucket [.replaceable]`<bucket-name>` --node [.replaceable]`<node-name>` \
    --duration 5m --interface eth0 --filter "tcp port 443"

# Preview the YAML without applying
python3 start-capture.py --bucket [.replaceable]`<bucket-name>` --node [.replaceable]`<node-name>` --dry-run
----
+
The script requires Python 3 with `boto3` and `pyyaml` installed, and `kubectl` configured for your cluster.
+
The script generates a `NodeDiagnostic` resource like the following. This example is provided for reference; note that the `upload` fields require pre-signed S3 POST credentials that are generated programmatically by the script.
+
[source,yaml,subs="verbatim,attributes,quotes"]
----
apiVersion: eks.amazonaws.com/v1alpha1
kind: NodeDiagnostic
metadata:
  name: [.replaceable]`<node-name>`                    # Required: node instance ID
spec:
  packetCapture:
    duration: "30s"                       # Required: capture duration (max 1h)
    # interface: "eth0"                   # Optional: default is primary ENI. Use "any" for all interfaces
    # filter: "tcp port 443"             # Optional: tcpdump filter expression
    # chunkSizeMB: 10                    # Optional: file rotation size in MB (1-100, default: 10)
    upload:                               # Required: pre-signed S3 POST credentials
      url: "https://[.replaceable]`<bucket>`{empty}.s3.amazonaws.com/"
      fields:
        key: "captures/[.replaceable]`<node-name>`/$\{filename}"
        # ... other pre-signed POST fields (generated by the script)
----

== Step 3: Monitor capture progress

Check the status of the capture.

[source,bash,subs="verbatim,attributes,quotes"]
----
kubectl describe nodediagnostic [.replaceable]`<node-name>`
----

The status will show:

* `Running` while the capture is in progress.
* `Completed` with reason `Success` when the capture finishes and all files are uploaded.
* `Completed` with reason `Failure` if the capture encountered errors.

To see the full status including `captureID` (used for S3 path identification):

[source,bash,subs="verbatim,attributes,quotes"]
----
kubectl get nodediagnostic [.replaceable]`<node-name>` -o jsonpath='{.status.captureStatuses}'
----

== Step 4: Download capture files from S3

Once the status shows `Success`, download the capture files from S3.

[source,bash,subs="verbatim,attributes,quotes"]
----
aws s3 cp s3://[.replaceable]`<bucket-name>`/captures/ ./captures/ --recursive
----

The files are gzip-compressed pcap format. Decompress and analyze with tcpdump or Wireshark:

[source,bash,subs="verbatim,attributes,quotes"]
----
gunzip captures/*.gz
tcpdump -r captures/capture.pcap0000 -n
----

== Step 5: Clean up

`NodeDiagnostic` resources are not automatically deleted. Clean up after you have obtained your capture files. Deleting the resource while a capture is running will stop the capture immediately.

[source,bash,subs="verbatim,attributes,quotes"]
----
kubectl delete nodediagnostic [.replaceable]`<node-name>`
----

== Configuration options and behavior

For the full `packetCapture` spec reference, configuration options, and behavior details, see the https://github.com/aws/eks-node-monitoring-agent/blob/main/docs/packet-capture.adoc[packet capture documentation] in the node monitoring agent repository.
