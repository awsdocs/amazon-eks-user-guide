[#sandboxing-exec-logs]
== kubectl exec and logs

In isolated mode, `kubectl exec` and `kubectl logs` work identically to standard pods. In confidential mode, the Cedar policy denies `exec` and `stdin` by default. Logs remain permitted in both built-in profiles.

[#sandboxing-developing]
== Developing with sandboxes

Use the isolated profile for development and testing. It allows `exec`, `stdin`, stats, and log streaming, and skips overlay encryption for faster pod startup:

[source,bash,subs="verbatim,attributes"]
----
eks-nitro-sandbox-genpolicy --profile isolated manifest.yaml
----

A minimal development pod spec:

[source,yaml,subs="verbatim,attributes"]
----
apiVersion: v1
kind: Pod
metadata:
  name: my-app
  annotations:
    sandbox.amazonaws.com/policy: "<base64 policy from genpolicy>"
spec:
  runtimeClassName: isolated-sandbox
  terminationGracePeriodSeconds: 0
  containers:
  - name: main
    image: public.ecr.aws/amazonlinux/amazonlinux:2023
    command: ["sleep", "3600"]
    resources:
      limits:
        cpu: "1"
        memory: 512Mi
----

[#sandboxing-list-sandboxes]
== Listing active sandboxes

The shim binary includes a `list` subcommand that queries `containerd` for all running Nitro Sandboxes:

[source,bash,subs="verbatim,attributes"]
----
sudo containerd-shim-nitro-sandbox-v2 list
----

Example output:

[source,bash,subs="verbatim,attributes",role="nocopy"]
----
SANDBOX ID                                                        POD
a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4e5f6a1  default/my-app
----

[#sandboxing-connect]
== Connecting to a sandbox

Once you have the sandbox ID, run diagnostic commands against the guest:

[source,bash,subs="verbatim,attributes"]
----
sudo containerd-shim-nitro-sandbox-v2 debug <sandbox-id> ls /
sudo containerd-shim-nitro-sandbox-v2 debug <sandbox-id> cat /etc/os-release
----

Or open an interactive shell:

[source,bash,subs="verbatim,attributes"]
----
sudo containerd-shim-nitro-sandbox-v2 debug <sandbox-id>
----

[NOTE]
.Root privileges required
====
Both `list` and `debug` require root because they access the containerd socket and the Firecracker vsock path under `/var/lib/nitro-sandbox/`.
====

[#sandboxing-dev-workflow]
== Typical development workflow

. Write your Kubernetes manifest.
. Generate a policy with the isolated profile: `eks-nitro-sandbox-genpolicy --profile isolated manifest.yaml`
. Set the base64-encoded policy from `genpolicy` as the `sandbox.amazonaws.com/policy` annotation.
. Apply the manifest: `kubectl apply -f manifest.yaml`
. List sandboxes to find the sandbox ID: `sudo containerd-shim-nitro-sandbox-v2 list`
